# 세션: 2026-06-24

## 작업: 애니화(AnimeGAN) 제대로 동작시키기 — 고품질 + 미리보기 + GPU

### 문제 (왜 애니화가 "안 됐나" — 코드 근거)
1. 미리보기 미연결: `_display_frame`(video_panel.py) 조건에 `_show_anime_var`가 없고,
   체크박스 라벨이 "🎨 내보내기 전용" → 체크해도 미리보기 변화 없음.
2. AnimeGAN 모델 파일 0개 + 기본 스타일 "animegan" → 항상 저품질 OpenCV 폴백.
3. onnxruntime CPU 전용(provider: Azure/CPU) → RTX 5070 미활용.
4. OpenCV 폴백 품질 낮음: `bitwise_and(color, edges)`로 어둡고 거침.

### 사용자 확정
- 방향: 고품질 AnimeGAN + GPU
- 모델 아티팩트 → 더 깨끗한 모델로 교체
- WSL2 GPU 셋업 시도

### 구현
#### src/anime_converter.py
- `apply_opencv_anime`: bilateral 5회 + k-means 색상 양자화(`_quantize_colors`) +
  검은 윤곽선 오버레이로 교체 (셀 셰이딩 품질↑).
- `apply_anime_to_person(... range_mode="person"|"full")` 추가. "full"이면 마스크/합성
  생략하고 전체 프레임 변환.
- `AnimeGANConverter`: 입력 레이아웃 자동 감지(**NHWC/NCHW**) + 고정/동적 입력크기 대응.
  (모델마다 레이아웃·고정해상도가 달라 기존 NHWC 고정 가정이 깨졌던 문제 해결.)

#### src/video_panel.py
- `_find_default_anime_model()`: `models/*.onnx` 자동 탐지 → 기본 모델 자동 선택.
- `_get_anime_converter()`: 선택 모델로 1회 로드 후 캐시 재사용.
- `_detect_landmarks()` + `_apply_anime()`: 미리보기/내보내기 공용. 재생 중 3프레임마다
  변환(스로틀) + 검출 캐시 재사용.
- `_display_frame`에 애니화 적용(애니화 먼저 → 오버레이). 체크박스 라벨
  "🎨 애니화 (미리보기+내보내기)"로 변경, 토글/옵션 변경 시 `_refresh_frame`.
- 범위(사람만/전체화면) 라디오 UI 추가. 내보내기 경로에도 `range_mode` 전달.

#### app.py
- `_collect_lib_paths()`: `lib/`(libGLESv2) + `nvidia/*/lib`(CUDA/cuDNN 휠) 경로 수집해
  LD_LIBRARY_PATH 설정 후 재실행 → GUI에서 GPU 애니화 자동 활성.

### 모델 (models/)
- 최종 채택: AnimeGANv2_Hayao_v2.onnx(기본, 정렬상 자동선택), AnimeGANv2_Shinkai.onnx,
  face_paint_512_v2.onnx (HuggingFace vumichien/akhaliq).
- 제거: AnimeGANv3_Hayao(frankminors, NCHW 504×672) — 머리/손 잡색 아티팩트 + 느림.

### 런타임 설치 (WSL2, --break-system-packages)
- onnxruntime(CPU) 제거 → onnxruntime-gpu 1.24.4
- nvidia-cudnn-cu12 9.23 / cublas 12.9 / cuda-runtime 12.9 / cufft / curand / nvrtc / nvjitlink

### 테스트 결과 (헤드리스 실제 실행)
- CUDAExecutionProvider 로드 성공 (RTX 5070 Blackwell sm_120, ort 1.24.4 + CUDA 12.9 OK).
- AnimeGANv2_Hayao_v2: GPU ~54ms/프레임 (CPU ~400ms 대비 ~7배). 전체 파이프라인(720×1280)
  852ms(초기 1회) → 이후 캐시/세션 재사용.
- 실프레임(Male Walk.mp4) 변환 결과 시각 확인: 깔끔한 Hayao 애니풍 (`/tmp/anime_gpu_final.png`).
- 개선된 OpenCV 폴백도 깔끔한 셀 셰이딩 확인(`/tmp/anime_opencv.png`).
- `python3 app.py` 기동 스모크: 정상 기동(크래시 없음), DISPLAY=:0.

### 미확인 (사용자 GUI 인터랙티브 확인 필요)

  토글 → 내보내기 mp4 품질까지의 클릭 플로우 (헤드리스로는 검증 불가, 사용자 확인 권장).

## 작업 2: 애니화 품질 개선 — White-box Cartoonizer "카툰(깨끗)" 추가

### 배경
- AnimeGANv2 결과 품질이 "구리다" → 사용자 확정: "깨끗한 플랫 카툰"(White-box
  Cartoonization, CVPR 2020) + "품질 최우선(느려도 OK)".

### 모델 확보 (models/)
- PINTO_model_zoo `019_White-box-Cartoonization`의 resources.tar.gz(Wasabi S3)에서
  `white_box_cartoonization_1x3x720x720.onnx` 추출 → `models/whitebox_cartoon_720.onnx`.
- **혼합 레이아웃**: 입력 NCHW `[1,3,720,720]`, 출력 NHWC `[1,720,720,3]`,
  `(img/127.5)-1` 정규화. (기존 가정 "입출력 동일 레이아웃"이 깨짐 → 첫 시도 줄무늬 노이즈.)

### 구현
#### src/anime_converter.py
- `AnimeGANConverter`에 `_out_layout` 추가 — 출력 레이아웃을 입력과 독립적으로 감지.
  `convert()`의 출력 transpose 조건을 `_layout` → `_out_layout`으로 변경.
- `apply_anime_to_person`: 변환 분기를 style 무관하게 `converter.loaded` 기준으로 변경
  (whitebox/animegan 공용, converter 없으면 OpenCV 폴백).

#### src/video_panel.py
- 스타일 라디오에 `("whitebox","카툰(깨끗)")` 추가 + 기본값 `whitebox`.
- `_find_whitebox_model()` 신규, `_find_default_anime_model()`은 whitebox 제외.
- `_get_anime_converter(model_path)`로 일반화(캐시 키=인자 경로).
- `_apply_anime`/`_on_anime_style_change`/내보내기 경로에서 whitebox→내장모델,
  animegan→선택모델로 분기. whitebox 시 모델 버튼 비활성+"내장 모델" 라벨.

### 테스트 (헤드리스 실제 실행)
- 변환기: in_layout=nchw / out_layout=nhwc / fixed=(720,720), CUDAExecutionProvider,
  워밍 후 ~30ms/프레임. 첫 시도 줄무늬→레이아웃 수정 후 깔끔한 플랫 카툰 확인
  (`/tmp/whitebox_class.png`, `/tmp/whitebox_panel_person.png`).
- VideoPanel 빌드 OK: 기본 whitebox, 모델버튼 disabled+라벨 정상, animegan 토글 시
  버튼 활성+AnimeGANv2_Hayao_v2.onnx 표시, 다시 whitebox 복귀 정상.
- `_apply_anime`(person 범위, InsightFace 검출 포함) 미리보기 경로 정상 출력.

### 미확인 (사용자 GUI 인터랙티브)
- 실제 app.py 클릭 플로우(미리보기 즉시 반영, 내보내기 mp4 품질) 최종 확인 권장.
